# Claude Code V2 实现卷 (01-08)

导航：[`首页`](../README.md) | [`总索引`](../master-index.md) | [`上一站：架构卷`](../architecture/01-04.md) | [`下一站：机制卷`](../mechanisms/01-07.md)

本卷沿着真实任务主链，记录 Claude Code 的关键实现链路。

## 01 CLI 分发与极速路径

- 图谱引用：[`02-cli-dispatch.svg`](../figures/02-cli-dispatch.svg)
- 实现文件：[`../src/entrypoints/cli.tsx`](../../src/entrypoints/cli.tsx)
- 关键点：
  - `--version` 走零依赖快路径。
  - `--dump-system-prompt` 只加载最小配置与 prompt 模块。
  - `bridge`、`daemon`、`remote-control` 说明它从一开始就不是纯 TUI 产品。

## 02 输入预处理

- 图谱引用：[`05-process-user-input.svg`](../figures/05-process-user-input.svg)
- 实现文件：[`../src/utils/processUserInput/processUserInput.ts`](../../src/utils/processUserInput/processUserInput.ts)
- 关键点：
  - 识别 slash commands。
  - 处理 hooks 与 bridge-safe command。
  - 判断 `shouldQuery`，决定这轮是否真的进入模型调用。

## 03 查询引擎逻辑

- 实现文件：[`../src/QueryEngine.ts`](../../src/QueryEngine.ts)
- 主链：
  1. `submitMessage()`
  2. `fetchSystemPromptParts()`
  3. `recordTranscript()`
  4. `query()`

它是自动化、交互式 UI 与子任务复用的共同会话入口。

## 04 循环控制

- 图谱引用：[`04-query-kernel.svg`](../figures/04-query-kernel.svg)
- 实现文件：[`../src/query.ts`](../../src/query.ts)
- 关键点：
  - token budget 与续轮控制。
  - 截断恢复与 “Resume directly” 类续写策略。
  - 模型调用、工具运行、stop hooks 与 compact 的编排。

## 05 工具上下文与工具池

- 实现文件：[`../src/Tool.ts`](../../src/Tool.ts), [`../src/tools.ts`](../../src/tools.ts)
- 关键点：
  - `ToolUseContext` 是工具运行时的统一横切上下文。
  - `assembleToolPool()` 合并 built-in tools 与 MCP tools。
  - 权限检查不是 UI 附件，而是工具协议的一部分。

## 06 会话存储与恢复

- 图谱引用：[`08-session-lifecycle.svg`](../figures/08-session-lifecycle.svg)
- 实现文件：[`../src/utils/sessionStorage.ts`](../../src/utils/sessionStorage.ts)
- 关键点：
  - transcript 主底座是 JSONL。
  - `~/.claude/projects/` 下的持久化结构支撑恢复、压缩边界与子代理记录。

## 07 API 流式处理与预算

- 实现文件：[`../src/services/api/claude.ts`](../../src/services/api/claude.ts)
- 关键点：
  - 流式输出和 thinking 块处理。
  - 工具输出预算控制与超限退盘。
  - tracing 与审计信息为后续观测层提供抓手。

## 08 任务生命周期与子代理

- 关键目录：[`../src/tasks`](../../src/tasks)
- 关键工具：[`../src/tools/AgentTool/AgentTool.tsx`](../../src/tools/AgentTool/AgentTool.tsx)
- 关键点：
  - 本地与远程任务不是两个孤立系统。
  - 子代理继承权限模式，但拥有独立消息栈与任务生命周期。
  - transcript 是多执行形态共用的恢复底座。

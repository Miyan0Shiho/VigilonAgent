# Claude Code 核心机制解析 (01-07)

导航：[`首页`](../README.md) | [`总索引`](../master-index.md) | [`上一站：实现卷`](../implementation/01-08.md) | [`下一站：用户卷`](../users/01-terminal-and-power-users.md)

本文聚焦 Claude Code 的六类核心机制：Tool、Skill、Hook、Permission、MCP、Subagent，以及与它们强绑定的 Telemetry。

## 1. Tools

- 核心入口：[`../src/tools.ts`](../../src/tools.ts)
- 工具协议：[`../src/Tool.ts`](../../src/Tool.ts)
- 关键结论：
  - 内置工具通过统一注册表组装。
  - `assembleToolPool()` 负责把 built-in tools 与 MCP tools 合流。
  - 工具池顺序本身会影响 prompt cache 与模型可见能力边界。

## 2. Skills

- 核心文件：[`../src/skills/bundledSkills.ts`](../../src/skills/bundledSkills.ts)
- 关键结论：
  - skill 不是简单 prompt 片段，而是工具、元数据、文件与指令的可复用包。
  - Claude Code 会在调用时提取关联文件，使模型可以再用 Read / Grep 检索 skill 内容。

## 3. Hooks

- 核心文件：[`../src/types/hooks.ts`](../../src/types/hooks.ts)
- 关键结论：
  - hooks 覆盖 SessionStart、PreToolUse、PostToolUse、PermissionRequest 等关键节点。
  - 它们可以阻断执行、修改输入，或介入审批链，而不是只做旁路日志。

## 4. Permissions

- 图谱引用：[`07-permission-boundary.svg`](../figures/07-permission-boundary.svg)
- 核心文件：[`../src/types/permissions.ts`](../../src/types/permissions.ts)
- 关键结论：
  - 权限模式、决策行为和自动审批分类器都被显式建模。
  - 权限不是“命令执行前弹个窗”，而是工具调用协议与产品治理的核心组成部分。

## 5. MCP

- 核心文件：[`../src/services/mcp/client.ts`](../../src/services/mcp/client.ts)
- 相关工具池：[`../src/tools.ts`](../../src/tools.ts)
- 关键结论：
  - MCP 为 Claude Code 提供动态工具与资源面。
  - 认证状态、资源读取与工具可见性之间存在真实联动。

## 6. Subagents

- 图谱引用：[`01-product-surface.svg`](../figures/01-product-surface.svg)
- 核心文件：[`../src/tools/AgentTool/AgentTool.tsx`](../../src/tools/AgentTool/AgentTool.tsx)
- 关键结论：
  - `AgentTool` 是委派与异步任务的统一入口。
  - worktree / remote 等隔离形态说明 subagent 不是“同线程换个 prompt”。
  - 生命周期、通信与递归保护都有专门的运行时处理。

## 7. Telemetry

- 核心文件：[`../src/cost-tracker.ts`](../../src/cost-tracker.ts)
- 关键结论：
  - 成本、时延、代码改动与 advisor 使用都会被持续记录。
  - 这层既服务产品观测，也服务任务恢复与治理。

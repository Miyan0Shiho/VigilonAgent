# Phase 2 新方向：以人类社会逻辑为基础的 Agent 社会

## 一、为什么上一版设计错了

上一版（`evolve.ts` + 6 个行为模块 + 消息通道方案）的共同问题是：**把 Agent 社会理解成了"Agent 之间的通信系统"**。

- 消息通道只是物理层：A 怎么把话说给 B 听
- Speech act 只是语法层：话说出来的格式是什么
- 规则引擎只是调度层：谁在什么时候做什么

这三层加起来不等于社会。正如同：

> 电话网络 + 语法规则 + 日程安排 ≠ 人类社会

人类社会的运行逻辑不是"通信协议"定义的。它是由**身份、关系、社会资本、规范、制度、冲突与修复、知识分层、权力结构**共同构成的。Agent 社会如果要有意义，必须回答同样的结构性问题。

## 二、人类社会的核心运行逻辑（Agent 社会必须遵守的）

### 1. 身份与连续性

一个人今天和昨天是同一个人——哪怕学到了新东西、改变了观点、经历了挫折。身份连续性是社会信任的基础。如果每次见面你都是"新的人"，社会无法建立。

**Agent 映射**：Phase 1 的 transcript + session memory 是 Agent 的身份基础。Sleep/Wake 不是"重新开始"，而是在保持身份连续性的前提下整合新经验。

→ 对应 Problem Map：意图形成、长周期连续性、记忆与身份所有权

### 2. 关系不是分数，是互动历史的函数

你信任一个人，不是因为你们之间有个数字从 50 变成了 58。数字只是影子，真身是：
- 你们合作过什么
- 对方失约过吗
- 对方在你需要时帮助过你吗
- 别人怎么评价 ta
- 最近一次互动是愉快还是糟糕

**Agent 映射**：信任/声誉不应该是 `updateTrust(A, B, +8)` 的机械操作，而应该是从互动历史中**可查询、可溯源、可争议**的统计推断。每个 Agent 对同一个人的判断可以不同，因为互动历史不同。

→ 对应 Problem Map：集体 agency 治理、背书与质疑、多 Agent 责任归属

### 3. 社会资本会累积也会贬值

做了 10 件好事积累的信誉，会随着一次重大失误大幅缩水。长期不互动的老朋友，信任会自然衰减。社会资本有：
- **获取规则**：怎么挣来的（履历、表现、他人背书）
- **贬值规则**：怎么失去的（失误、失信、时间衰减）
- **转化规则**：能力的声誉能不能转化为决策权

**Agent 映射**：声誉不是 5 维分数，而是一个有来源、有时间戳、有权重的"信任档案"。每次互动后不是机械加减，而是**基于互动结果更新档案**。

→ 对应 Problem Map：agency 经济学、代价与收益归因

### 4. 规范从先例中涌现

"我们团队删目录前都会先检查子模块"——这不是谁规定的，是上次出事之后大家自然形成的。规范的特征：
- 不是提前设计的
- 从具体事故/争议中产生
- 被群体默会地遵守
- 违反时会引发社会反应

**Agent 映射**：Skills/Rules 不应只是从单个 session 中 LLM 提取出来的文本。它们应该是**社会反复验证过的先例**——某条规则被多次争议引用、被多个 Agent 采纳后，才升级为社会规范。

→ 对应 Problem Map：需求协商、动态规划、事故学习

### 5. 冲突是正常的，修复机制才是社会

好的社会不是没有冲突，而是有成熟的冲突处理机制：表达异议 → 被听见 → 协商 → 妥协或裁决 → 修复关系 → 形成先例。坏的社会只有压制或升级。

**Agent 映射**：Dispute 不是 approve/block 的二元结果，而是一个多阶段过程。关键的不是"谁赢了"，而是：
- 异议是否被记录（少数意见保留）
- 裁决是否形成先例
- 双方关系是否在争议后被修复
- 如果争议升级到用户，用户裁决是否被社会吸收

→ 对应 Problem Map：需求协商、集体治理、长周期连续性

### 6. 知识分层：私有的、共享的、公认的

- **私有**：只有 A 知道，B 不知道
- **共享**：A 和 B 都知道，但不一定都同意
- **公认**：社会所有成员都接受的事实（"这个项目用 pnpm"）
- **遗忘**：曾经公认但已经过时或错误的知识

**Agent 映射**：不是每个 Agent 都有一份全局记忆。知识有 scope、有 owner、有 expiry。Phase 2 的共享记忆空间分层管理这些知识。

→ 对应 Problem Map：知识代谢、环境适应、对抗安全

### 7. 角色从行为中涌现，但会反过来约束行为

你在团队里"是"那个人，不仅因为别人叫你什么，更因为你反复做了什么事。但一旦角色形成，它会反过来影响：别人找你做什么事、给你什么权限、对你说什么话。

**Agent 映射**：角色不是预设标签，也不是纯统计分类。它是**行为模式 + 社会期望 + 自我认知**的复合体。检测到角色后，应该影响：消息路由（"这事应该找 ta"）、权限建议、信任推断。

→ 对应 Problem Map：自适应 stewardship、劳动重组

### 8. 制度是固化了的互动模式

重复的互动会固化为规则、流程、角色、权限。制度不是设计的，是长出来的。但一旦固化，就可以被审视、被修改、被废除。

**Agent 映射**：Skills 是固化的成功经验，Rules 是固化的事故教训，Roles 是固化的行为模式。它们都从互动历史中提炼，但可以被新的互动推翻。

→ 对应 Problem Map：企业安全、评估与供应链、法律可委托性

## 三、产品如何落地：给定一个活社会，让它继续长

研究成果正确：社会需要涌现。但产品不能从 0 开始。解决方法是：**预埋一个已经运行过的社会，用户打开时看到的不是空白，而是一个有故事、有关系的活体。**

### 3.1 初始态（Bootstrap State）

用户打开 Phase 2 时看到的社会，由以下预埋数据构成：

1. **3 个 Agent 的初始互动历史**（12-20 条事件）
   - 包含：一次成功的合作、一次有惊无险的争议、一次观察评估
   - 来源：现有的 test fixtures，但需要更丰富

2. **从互动历史中计算出的初始信任网络**
   - 不是随机数，是从历史中可溯源的
   - 例如：executor→reviewer 信任较高，因为 reviewer 上次阻止了事故

3. **从互动历史中提炼的初始声誉**
   - 每个维度都有来源：某次事件导致了某个评分

4. **1-2 条社会规范**
   - "删除目录前检查子模块"——来自上次争议

5. **共享知识空间**
   - 项目背景、用户偏好、已知风险

### 3.2 产品体验

用户打开页面 → 看到的是一个已经"活着的"社会：
- 3 个 Agent 在 canvas 上，彼此之间有可见的关系线（粗细=信任度）
- 侧边栏显示最近互动历史（不是空白的）
- 社会状态面板：信任网络、声誉分布、角色标签、活跃规范
- 用户可以：发起新任务（Agent 自主互动）、查看社会历史、调整参数

新的互动在已有基础上生长，社会不是从 0 开始，而是从一个有故事的起点继续向前。

## 四、从研究到产品的映射

| 研究发现 | 产品含义 |
|---------|---------|
| 三角闭合自发产生 | 不需要设计"推荐合作对象"算法，Agent 自己会通过共享熟人找到彼此 |
| 优先连接导致富者越富 | 需要设计"社会资本贬值"机制，避免头部 Agent 垄断所有互动 |
| 同质性导致群体分裂 | 需要设计"跨群体互动"机制，偶尔强制不同意见的 Agent 互动 |
| 集成瓶颈是大社会的核心问题 | Sleep/Dream 是解决集成瓶颈的机制——不是定时触发，而是检测到整合不足时触发 |
| 基础模型选择是最重要的变量 | 产品应该让用户看到"不同模型下社会动态不同"，而不是只支持一个模型 |

## 六、新的实现顺序

### 第一阶段：基础数据结构
1. **重写 `workspace.ts`**：定义互动历史（MessageLog）、信任档案（TrustProfile）、社会共识（SharedKnowledge）、规范库（NormLibrary）
2. **Bootstrap 脚本**：从 fixtures 生成初始社会状态（12-20 条互动 + 信任 + 声誉 + 1-2 条规范）

### 第二阶段：观察层
3. **重写 `reputation.ts`**：从互动历史中统计计算信任/声誉，每条评分可溯源
4. **重写 `roles.ts`**：适配新的数据来源

### 第三阶段：冲突处理
5. **重写 `dispute.ts`**：多阶段冲突处理（异议 → 协商 → 裁决 → 修复 → 先例）

### 第四阶段：社会整合
6. **重写 `sleepWake.ts`**：检测整合不足 → 触发社会级 Dream → 更新共识 + 提炼规范
7. **更新 `dream.ts`**：从单 Agent 记忆整理 → 跨 Agent 社会事件整合

### 第五阶段：前端与 API
8. **重写 `demo.ts`**：Bootstrap 加载 + 状态查询 + 互动记录 API
9. **更新前端**：展示互动历史溯源、信任档案、规范库
